# 近地起飞阶段与验证 · 2026-10-29

版本：`J31-20261029-NEAR-LIFTOFF`。最初基于已由用户烧录并静态验证的测距单位修复版另存，2026-10-30 按用户要求同步到 `Remote and mini 5.0`。此前另存交付保留，本次不生成压缩包、不烧录或试飞。400 PWM 不是已标定悬停推力。

## 为什么新增这一阶段

用户确认：激光窗口正常落地距泡沫板约 10 mm，过近时硬件没有有效输出；软件不能从无效值判断真实高度。此前代码要求有效高度才准许 C3，因此地面按 C3 会立即报前置条件故障，或被偶发小高度误导而进入没有可靠反馈的原路径。单位修复解决了十倍读数错误，无法消除硬件近地盲区。

用户选择方案 A：允许一段有推力和时限约束、没有高度反馈的起飞阶段；取得可靠测距后恢复高度闭环。本实现不把无效激光伪造为 0 mm，不把最后一次 766 mm 缓存当作当前高度，也不把近地阶段算作到位、稳定悬停或检光成功。

## C3 的实际流程

1. 正面朝上、地面水平静止，光源关闭，上锁收集至少 5 个 BH1750 环境样本。油门低→高保持至少 60 ms→低完成人工解锁，之后维持油门不高于 1050、其他三轴回中。
2. 若解锁后尚未启动过电机，且高度无效或不足 200 mm，按 C3 可进入近地阶段。要求 IMU 健康、模块通信在 30 ms 内成功、光感健康且基线足够，横滚/俯仰均不超过 8°。软件没有独立地面开关，操作者必须确认机身在地面。
3. 模式保持 `mode=3`、阶段 `phase=1`，`j_flight.near_active=1`。保持水平姿态和进入时的偏航目标；暂不使用高度/光流闭环，不响应普通方向杆，不计稳定或光源任务。LED 全灭是调高状态，不能据此判断故障。
4. 公共推力从 0 按最多 450 PWM/s 上升至 400 PWM，约 0.89 秒达到目标。400 是姿态混控前的公共分量；各电机还叠加姿态 PID，最终各路仍按 0～1000 限幅。软件也把近地公共目标限制在自动上限及手动可达上限内。
5. 同时要求健康高度至少 200 mm、垂速有效且有限、读取时间戳晚于本次 C3，至少两次不同读取时间戳，连续满足 100 ms，才退出近地阶段。低值、无效、陈旧或确认中断会清掉本次确认。模块没有物理测量序列号；这里的时间戳表示主机读取，不等于已证明独立物理帧。
6. 接管当周期保留公共推力，目标高度从当时实测值开始，以原 250 mm/s 目标斜率走向 800 mm，垂速积分按当前推力预置并受限。后续输出仍受 450 PWM/s 限制。开始 C3 时的原调高计时不因测距接管重置。
7. 若从近地开始经过 2000 ms 仍未满足接管，直接上锁、四路 PWM 清零，故障 9。进入闭环后再失去测距，使用原有激光故障接管窗口，不会自动回到近地推力阶段。

每次人工解锁只发放一次近地启动资格，首次起转即消耗。手动起飞后落地、低杆软停、换模式或反复按 C3 都不能恢复资格。需要重新开始时，先 C2 上锁，再执行完整人工解锁。C3 重按不延长 2 秒期限。已进入普通闭环时的控制逻辑保留。

## C2、C4 和故障

C2 和原低油门加偏航左的组合仍最高优先。上行失联、IMU 无效、控制停顿保护保持；近地横滚/俯仰超过 15°立即停机，模块通信失败或超过 30 ms 未成功读取也停机。近地高度无效本身不立即报错，这是方案 A 的目的。

C4 在近地阶段提出人工接管请求：停止继续爬升推力，保持提出请求时的公共推力，继续姿态控制，按原手动公式进行油门对位。三轴回中、遥控帧足够新且持续匹配 200 ms 后转人工，成功后由人负责油门；再次 C4 可取消并继续原推力斜坡。按下、取消 C4 均不重置近地 2 秒期限，未成功接管到期仍停机。若测距先恢复，则转入有实测高度的普通 C4 对位。

手动公式仍为 `200+0.45×(通道−1000)`。近地达到 400 PWM 后，约通道 1445 可匹配；机械杆位须实测，不能把该通道值直接等同固定杆位百分比。若太早按 C4、公共推力尚低于手动可达范围，会提示不可匹配并四短鸣；可取消请求，急停用 C2。首次验收宜先分别检查近地超时和 C2，再单独检查接管。

| 现象 / 故障码 | 含义 |
| --- | --- |
| C3 后 LED 全灭、近地无四短鸣 | 允许的近地起飞过程；仍须看变量确认当前阶段。 |
| 按 C3 立即四短鸣，故障 8 | 前置不满足：例如未回到底杆、姿态不平、光感/基线/通信不合格，或没有本次启动资格。 |
| 近地约 2 秒后停机并四短鸣，故障 9 | 没在期限内取得可靠测距，拆桨且固定在近地时属于预期。 |
| 近地提前停机，故障 4 / 5 | 超过近地 15°姿态门限 / 模块通信失效或陈旧。 |
| 故障 1 / 2 / 3 / 13 | 急停 / 上行失联 / IMU / 控制周期超时。 |
| C4 后方向声和四短鸣交替 | 可能推力不可匹配或已有故障；四短鸣不能唯一确定原因，要读 fault/align。 |

## 拆桨复核顺序

用户打开本目录 `flight/mini.uvprojx` 编译下载，或使用 `firmware/basic/flight_basic.hex`。现有配套 J31 遥控器无需重烧。下载结束后退出调试，将电池、USB 和可能供电的 J-Link 接线全部断开约 5 秒，再正放静止重新供电。上一轮单位修复烧录后曾需完全断电才离开下载状态，不要仅凭 Download 成功认定主程序已经运行。

1. 全部拆桨，正常落地，保持油门最低和其他杆回中。确认上锁轮亮、`armed=0`、`motors_on=0`、四路 PWM 为 0。
2. 人工解锁后底杆 C3，不改变高度。检查 `near_active=1`、`mode=3`、`phase=1`、`common` 从 0 上升且不超过 400，`enabled=0`、`arrival=0`；约 2 秒后停机、`fault=9`。近地没有测距时的超时是预期，不要反复放宽时限。
3. 重新解锁后单独测试 C2，确认不等 2 秒就清四路输出并上锁。机身勿翻面运行起飞测试。若需要动态观察，避免暂停 CPU；需要停下读数时先 C2 上锁。
4. 可靠测距接管先使用可固定目标和机身的台架条件：避免拿着正在输出的机身移动。若没有可控装置，暂不人为模拟此项；编译/回放通过不能代替后续受控实测。
5. 保存 `near_active`、`common`、`near_start_ms`、`near_valid_reads`、`j_sensor.value.height_mm/range_ok/velocity_ok/range_ms/module_ok/module_ms`、`fault/armed/motors_on` 和 `TIM2->CCR1..4`，用于下一步推力标定。不要把拆桨固定高度结果当作带桨升力验证。

本版 107 个 C 软件用例、102082 次断言通过；基础、单光源升级和 A/B 升级的实际 ARM 状态机各 6 项近地回放通过，另有 18 项 ARM 测距及 12 项 ARM 定时器检查。完整资源、日志和哈希见 `verification/构建与测试汇总.md`、`verification/最终核验.json`。回放使用合成传感器和遥控数据，没有建立飞行动力学模型。

400 PWM、450 PWM/s 和 2 秒是可审查的工程初值，尚不保证这架 113.11 g 样机能越过盲区，也不保证真实高度上限。进入时没有高度反馈，侧向也没有光流保持；到期直接断推力，已离地时会下落。必须先拆桨验收，再由用户在受控场地标定推力、姿态和接管，不能直接把软件通过当作自由飞行许可。旧手动增益 0.45、800 mm 目标、BH1750 独立 PA9/PA10 接线和 J31 协议均保留。
