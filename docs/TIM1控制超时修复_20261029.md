# TIM1 控制超时修复（2026-10-29）

版本：`J31-20261029-TIM1-RCR0`。

## 原因和代码修改

用户在拆桨台架上沿正中上拨、下拨完成解锁时复现四声短鸣。只读诊断取得故障码 `13/J_ERR_DEADLINE`、超时锁存标志 `j_deadline_fault=1`，电机输出为 0。TIM1 的 PSC=719、ARR=299、RCR=90；72 MHz 下更新周期为 273 ms，超过 25 ms 保护阈值。

`flight/CONFIG/TIM.c` 中的 `TIM1_Config()` 创建局部时基结构体后没有完整初始化，遗漏 `TIM_RepetitionCounter`。ST 库会将该字段写入高级定时器 RCR。ARMCC 还会使用保存寄存器的栈空间分配局部变量，因此未初始化成员可能继承调用前的寄存器值，不能依赖冷启动 RAM 为零。

本次修改仅在该函数补充：

```c
TIM_TimeBaseStructInit(&TIM_TimeBaseStructure);
/* 在已有 Period/Prescaler/ClockDivision/CounterMode 设置之后 */
TIM_TimeBaseStructure.TIM_RepetitionCounter = 0;
```

25 ms 超时保护、800 mm 目标高度、传感器接线、遥控协议和操作方法保持原设置。

## 构建与回归结果

- 基础飞控、单光源飞控、A/B 飞控均重新构建；基础飞控 Flash 28,412 字节，RAM 6,392 字节，保留原 IMU 标定页。每个飞控构建只有 3 条已存在的库告警，无新告警。
- 现有软件回归 93 个用例、101,514 次断言全部通过。
- 新增 `verification/verify_timer.py`，用 Unicorn 2.1.4 直接执行交付 HEX 中的 `TIM1_Config` 及其调用的真实 ST 库 ARM 机器码，AXF 仅提供入口符号。外设寄存器使用内存模型。
- 修复前：初始栈及寄存器填充 `0x5A` 时读到 RCR=90、周期=273,000 us，测试失败；填充 `0xA5/0xFF` 时也失败。零填充会偶然通过。
- 修复后：三种飞控固件分别覆盖 `0x00/0x5A/0xA5/0xFF`，12 个检查均通过，RCR=0、计算更新周期=3000 us、定时器和更新中断已使能。
- `finalize.py` 将这三份 ARM 回归结果与当前 HEX/AXF 的 SHA256 一并核对，避免用旧测试结果证明新固件。

该测试不模拟完整计时器运行或无人机动力学，也不等于修复后实板已验证。

## 固件和复现命令

优先使用 `firmware/basic/flight_basic.hex`。配套遥控继续使用现有 J31 `remote_basic.hex`，本次无需修改遥控代码。升级固件也已包含同一修复。

在本目录中，安装固定版本的测试依赖后可复现 ARM 初始化检查：

```powershell
python -m pip install unicorn==2.1.4
python -X utf8 verification/verify_timer.py
python -X utf8 verification/verify_timer.py --variant upgrade_single
python -X utf8 verification/verify_timer.py --variant upgrade_ab
```

也可将依赖安装到独立目录，再用 `--dependency-path 路径` 指定；测试不连接任何调试器。
